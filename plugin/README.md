# ONES 工作台（开发原型）

Orca `trusted-worker` + HTML 侧栏插件；图片/视频由插件内受控 Blob 展示，**无需修改或安装开发版 Orca 宿主**。最低声明版本为 1.4.254，本次状态功能验证宿主为 1.4.255。**尚未达到生产可用或完整方案验收；macOS 普通/批量工时新增已开放，描述更新与 Bug 创建/内容修改未开放；限定步骤的状态更新已开放；已增加手动确认后通过 CLI 创建修复聊天。**

## 已实现与边界

- ONES、Coho 独立账号密码表单，Worker 直接认证、身份回读、受保护令牌存储；不导入浏览器凭证。2026-11-09 两站插件登录及身份回读已验证；验证码/MFA/刷新尚未支持。
- “我的 Bug”仅分页查询本人负责的缺陷：先从权威配置解析缺陷类型 ID，再在服务端限定类型，拒绝混入其它工作项。不再显示冗余类型控件及 Bug 页团队选择；单团队自动使用当前团队，多团队首次须在登录页选择。首次打开或切回“我的 Bug”自动从第一页刷新，保留项目/状态筛选，手动刷新仍可用；旧请求会取消，失败不展示旧列表为最新。项目/状态筛选仅影响已读取缺陷，仍可续页。状态选项取缺陷类型默认配置，不是团队全集；默认待处理、重新打开、修复中，标签可删除、展开添加、全部/清空/恢复默认。工时页独立读取本人负责的普通“任务”（不含缺陷），不与 Bug 列表共用缓存或游标。列表移除“打开原单”“实施说明”按钮，整行（含右侧箭头）点击进入详情；原单入口仅保留在详情页。详情已接入完整正文、分页评论及附件清单；任意项目定制工作流不保证支持，未知字段/条件一律阻断。
- 项目筛选跟随 Orca 当前选中的工作区所属项目：优先复用已保存映射，否则唯一名称匹配（如 `SidusLinkPro` → `Sidus Link Pro 【IPOT】`）；无匹配、歧义或上下文不可用时显示全部已读取项目。需要 `workspace:read`。只在已加载的本人缺陷项目中筛选，续页会重新匹配，不改服务端查询或状态筛选。手动筛选在刷新/同项目终端变化时保留，切换到另一 Orca 项目后恢复跟随。
- 通过 `workspace.changed` / `workspace.readContext` 感知选择，不用插件 cwd 或 CLI `active` 推断。同名 `main` 工作区使用上下文终端 ID 与 CLI 清单归属消歧，再按项目稳定 ID 读取名称；CLI 返回的终端预览不展示、不保存。无终端且同名歧义、宿主不返回上下文（本机普通文件夹 fixture 已观察到）、权限不足、远端或清单截断均安全回退全部。迟到响应不得覆盖后来的选择。
- 按业务日期读取考勤及已有工时；自动识别正常打卡、手动分配任务、填写描述、保存草稿与生成额度预览。缺少考勤不能默认补足 8 小时。
- Worker 内含逐笔提交/回读、持久防重、未知结果阻断、原记录补描述校验；macOS 工时新增入口已开放，仍强制考勤、额度、普通任务、预览确认与防重校验；不提供绕过开关。记录核对页支持只读定位、人工确认本地恢复及原记录补描述预览，真实描述写入仍禁用。
- ATS 本人员工标识和考勤期按已核实的前端链路自动解析，禁止 UI 指定其他员工；单日读取已验证，其它租户/跨期/异常外勤仍不推断。
- 完整详情按顺序显示文字和受控图片/视频；同一个 HTML 面板展示完整详情，不加载远程网页或执行原单 HTML。图片支持静态 PNG/JPEG/WebP（边长不超过 4096），视频支持 MP4/WebM（依赖实际解码能力），单文件最多 32 MiB。超限、不支持或读取失败明确提示，提供“打开原单”；不静默截断、执行 HTML 或自动播放。评论与附件每页 20 条，可向前/向后翻页，不把首屏当作全部。正文保留文字、单换行和缩进；普通连续空行最多保留一个，去除首尾空白行及空白行中的 NBSP。HTML pre/code 保留原有文本空白；纯文本出现 Markdown 代码围栏时保守保留全文，不猜测代码语义。不承诺还原原单字体、表格布局、链接或所有富文本扩展。
- Bug 详情顶部最右侧及底部均提供“执行修复”：自动匹配 ONES 项目与 Orca 项目，唯一可靠匹配直接使用，无匹配/歧义/已绑定项目失效才手动选择。预检目标项目/CLI 与完整状态路径，补齐各步必填字段后，一次确认“开始修复并更新状态”；逐步回读到修复中才通过 CLI 在已有本地项目主目录新建聊天，不创建工作区。
- 映射使用 ONES 实例/账号/团队/项目身份隔离，并保存双方稳定 ID；名称只用于首次匹配，兼容空格、大小写、全角及尾部 `【标记】`，不使用模糊相似度。多个本地 setup、目录缺失或主目录歧义会阻断，不擅自选择任务 Worktree。
- 修复消息包含标题、正文、完整分页评论与媒体路径，并明确原单属于外部数据，不能覆盖插件生成的执行/回执协议。会话仅附四行执行摘要和本 run 私有 `receipt-instructions.md` 绝对路径；完整 JSON 模板、run/revision/token/sequence 规则只在插件生成的协议文件中，不混入外部原单内容。协议以 wx/0600 写入并同步完成后才启动；失败清理预启动预约，未知启动保留资料。单条 CLI 消息仍最多 48,000 UTF-8 字节，摘要/路径计入预算；超限不截断。媒体和分页预算保持不变。
- 媒体是本地文件引用，不是原生聊天附件，读取/解码与结果文件写入依赖 Agent 权限。媒体和启动账本位于 `~/Library/Application Support/ones-workbench/repairs`（目录 0700、文件 0600，未加密）；SQLite 位于相邻 `repairs-cache/cache.sqlite`，保存任务快照、执行投影和 Agent 自报摘要/证据，不保存 ONES/Coho 登录令牌。单次回执能力令牌只写入私有协议和结果文件，不在启动 prompt 内展开，数据库只保存令牌摘要；Agent 读取协议后的工具上下文仍可能保留令牌，不得公开分享这些文件。CLI 参数可能被本机进程检查工具读取。
- “实施”优先读取 SQLite 缓存，不等待 ONES；展示最后同步时间及过期/失败提示。30 秒内再次进入复用缓存，可见页每分钟定向同步已知任务，每 5 秒接收本地回执；手动刷新立即同步。首次及每 24 小时完整分页对账旧账本（仍限制 100 页/5,000 项/8 MiB），之后只查已知实施任务，单轮只读取一次缺陷类型。完整快照事务发布，scope/版本漂移拒绝覆盖。网络失败保留标记为可能过期的缓存；服务明确拒绝身份或权限则隐藏，账号/团队隔离。已转派或删除任务对账后隐藏，再次分配回来可恢复；缓存不是远端操作授权。
- 进入或刷新 Bug 详情时自动只读加载本地执行记录，显示发送状态、执行时间、目标项目与 Session；已有记录时入口为“查看执行记录”。读取失败明确提示并阻止启动，可重试查询，不视作未执行。
- 启动前独占创建并同步本地记录；聊天 ID 与消息 journal 回执才记作已发送，未知结果/终端降级禁止自动重试。已有记录只展示，不重新创建；目前不判断 Agent 是否已完成，也不自动重开后续修复。记录损坏、残留启动意图须人工核实，不能直接删除记录重试。关闭页面不保证取消已启动操作。
- CLI 暂无打开指定 session 的能力；界面显示目标项目、session ID 和媒体目录，用户在该项目下切换会话。确认会话已不再需要媒体后，可自行清理对应媒体子目录，保留启动记录以防误重发。
- CLI 使用平台对应的默认安装路径：macOS 为 `/Applications/Orca.app/Contents/Resources/bin/orca`，Windows 为 `%LOCALAPPDATA%\Programs\orca\resources\bin\orca.exe`。不走 shell 或 PATH；Windows Worker 的精简环境会补齐 CLI 定位本机运行时所需的用户目录变量，并隐藏子进程窗口。远程项目和自定义安装路径仍未覆盖。

### Windows 本地修复支持

Windows 的状态账本、修复资料与 SQLite 缓存位于 `%APPDATA%\Orca\plugins-data\local.ones-workbench\runtime`；解析 `plugins-data` 的目录映射后使用真实路径，因此把插件数据迁移到其它磁盘后，回执与媒体也会写入该磁盘。macOS 保留既有 `~/Library/Application Support/ones-workbench` 路径，不迁移历史账本。

Windows 使用实际 NTFS ACL 与文件所有者检查，代替不适用的 Unix uid/mode 判断。只允许当前用户、SYSTEM 和本机管理员访问；仅初始化当前用户所有的空目录，不自动收紧并接受已有不安全资料。符号链接、硬链接、超限回执、身份绑定和防重复执行检查继续生效。文件写入后仍执行同步及原子替换；Windows 不执行 Node 不支持的目录 fsync，不声称具备断电后的目录同步保证。

状态读取失败会直接展示具体原因及“重新读取”，不再显示没有可点击入口的“可打开查看原因”。Apple 受管测试证据仍按原有 macOS 路径和权限合同处理，本次未扩展至 Windows。

验证范围：Windows 真实 Orca Worker 的状态配置、执行记录和修复准备读取通过；定向测试覆盖状态提交防重、未知结果、文件权限、缓存回执及模拟 CLI 启动。未提交真实 ONES 状态变更、未启动真实 Bug 修复 Agent；完整业务链仍须单独验收。

需求及剩余验收见 [实施规划](../docs/orca-plugin-plan.md) 与 [验证报告](../docs/orca-plugin-verification.md)。考勤折算只按 [既定规则](../docs/coho-attendance-api.md#6-已确认的工时规则)，按已确认的正常工作时段及迟到半小时规则扣减额度，按当天 08:00 至次日 08:00 的窗口归属次日凌晨加班，不会推断缺卡或其它班次政策。

## 本机开发加载

在可信环境使用本机 Orca CLI，先阅读该安装版本的 `skills get orca-plugin-authoring`。从仓库根目录执行：

```sh
orca plugin types ./plugin
orca plugin validate ./plugin
orca plugin dev load ./plugin --json
```

首次加载会返回精确审批指纹。核对本机 Node Worker、插件自身存储、加密凭证存储及当前工作区只读权限，经用户同意后才使用返回的 `--approve` 参数；不要复制他人的指纹。随后：

```sh
orca plugin open local.ones-workbench --panel ones-workbench
# 临时验证完成后停用；不删除保存的凭证或业务数据
orca plugin dev unload ./plugin
```

媒体通过本插件 Worker 的分块接口读取；面板仅创建临时 Blob URL，不接收真实媒体地址或认证令牌，不扩大宿主 CSP/网络权限。图片按可见范围读取、视频点击加载且不自动播放；离开详情撤销资源。

开发文件变动会执行新代码；只加载可信源码。trusted-worker 能使用当前用户的本机权限，capabilities 不是完整操作系统沙箱。

## 登录与数据保护

会话生命周期：ONES 使用服务端 `expires_in`，到期前 60 秒按需使用 refresh token 续期，优先于保存密码重登；Coho 使用官方前端已核实的 `expTime` 秒数，缺失时保留未知有效期，每次考勤读取仍验证服务端身份。Coho 未发现可接入的 refresh token 协议，明确过期/认证失效后的自动恢复使用下面的用户授权密码登录，不虚构续期接口。HTTP 401 及 Coho JSON `code=401` 终止对应会话资格；网络、权限和普通业务错误不当作登出。

两个平台均提供「保存账号密码并自动登录」，默认关闭，只有勾选且本次登录成功后才把账号、密码、绑定身份及 ONES HTTP 风险同意写入宿主受系统保护的 `secrets`；普通 storage、配置、日志和 UI 状态不包含密码。UI 只回填保存的账号，不回填密码。取消勾选立即删除该平台保存凭据，保留仍有效会话；退出同时删除会话和保存凭据。保护不可用时不传输或写入密码。Vault 写入失败不发布成功状态，删除失败会报错，须重试删除，不宣称已删除。

恢复前台或新读取前发现会话过期时，仅已勾选平台允许自动登录。ONES 先续期，明确续期授权失效或无 refresh token 才使用保存的密码；网络续期失败不降级为密码登录。同站点并发共享一次自动登录；提交密码前持久化暂停标记，Worker 中途退出不会循环尝试。密码错误、验证码、身份变化或未知失败暂停，须手动登录修正；网络/限流失败至少退避 60 秒，普通状态刷新不会连续尝试密码。旧会话没有 refresh token 或保存凭据时仍需手动登录一次。

自动重登只恢复认证，不重放任何已失败的业务请求或写入；成功后旧预览、确认及展示缓存失效，需重新读取/确认。退出、取消保存、手动换号都阻止旧自动登录回写；取消/失败的手动登录不保留本次新密码。两站相互独立。重载从宿主 secrets 恢复，凭据库临时不可读不当作登出，不从浏览器或其它 profile 导入凭据。

同一插件身份和宿主数据目录下的普通重载应保留会话；卸载后重装不作保留承诺。本地 Orca 源码 `removeInstalledPlugin` 会删除插件数据目录（含凭据库）；更换 profile/安装身份也不能假定共享登录。不在插件外备份令牌来绕过宿主卸载策略。此为源码核查，尚未对安装版执行真实卸载/重装验收。

在插件界面输入凭证，不写入命令行、配置、测试或聊天。ONES 仅连接指定内网 HTTP origin，提交前必须确认传输风险；RSA/摘要不替代 TLS。Coho 固定已核实的 ATS 租户。网络禁止跨 origin 与自动重定向。

未勾选时密码仅用于当次认证；提交/取消/退出面板后清空输入引用。已勾选凭据及会话令牌仅进入宿主受保护的凭证库，保护不可用时拒绝认证。两站退出相互独立，身份改变使原业务确认失效。未支持的验证码、MFA、锁定等步骤停止，不循环重试。

草稿描述保存在插件普通本地存储，**不是加密保险箱**；不要填写凭证或非必要隐私。原始考勤、完整业务响应、Cookie、签名、日志与个人快照不纳入仓库。本插件没有遥测或浏览器令牌读取入口。

## 待核实操作与描述补全

在“记录核对”选择团队，读取待核实操作，再只读回查原日期完整工时。匹配同时校验任务、本人、日期时间、时长、描述摘要及操作前记录身份；唯一候选仍须人工确认归属，确认前再次回读，只更新本地账本。零匹配、多匹配、身份或记录变化均保持阻断，不能视为失败后重发。外部客户端可能同时写入，不承诺 exactly-once。

补描述从本人原日期工时选择空描述记录，单独确认文本，不要求 Coho 额度；保护原 key、任务、归属、类型、开始时间、时长及其它整日记录。结果不明也进入同一核对流程，禁止新增或删除重建。生产描述提交按钮和 Worker 闸门均仍关闭。

账本保存必要操作元数据、描述摘要与操作前 key，不保存原始描述；摘要不是加密。草稿可含原始描述，仍须遵守上面的本地隐私边界。核对成功使旧考勤预览失效，但不擅自删除保存的草稿；用户应重新核对是否已登记。

## 验证

`package-lock.json` 锁定开发类型工具；没有安装脚本或运行时 npm 安装；HTML 解析器 parse5 7.3.0 与 entities 6.0.1 已随源码打包，许可证与图片头部校验来源位于 `src/vendor/README.md`。可在授权环境 `npm ci --ignore-scripts --prefix plugin` 后执行 `plugin/node_modules/.bin/tsc -p plugin`。宿主声明由 `plugin types` 生成，不提交 `.orca/`。

- HTML 面板不再使用 components 的 `plugin check` 场景。`tests/html-panel.browser.mjs` 定义有界 UI 回归旅程，配合 `tests/fixtures/html-worker.ts` 与纯虚构 `fixture-assets.json`，在未修改的安装版 Orca 的隔离 HOME/userData 中执行；详细驱动与证据见验证报告。
- `tests/html-media.test.ts` 覆盖字节/格式/尺寸拒绝、取消迟到和 Blob 撤销；PNG、WebM 播放/暂停/定位由真实 Electron guest 验证，不以单元测试或截图替代。
- 定向测试使用安装版本官方 `orca-test-register.mjs` loader、`ORCA_PLUGIN_TEST_ROOT`，以 Node `--test-name-pattern` 选择具体风险用例及文件。loader 路径从本机安装确认，不下载另一版本替代。
- 不运行全量 `plugin test` 或通过拆批遍历全仓测试；准确执行记录见验证报告。

`plugin/tests/` 仅含虚构 fixture；与根目录整目录忽略的 `/tests/` 无关。当前没有 npm 发布或公开插件安装包授权。

详情顶部或实施列表“更新状态”面向“更新为已修复”这一业务目标：从权威元数据规划最短且唯一的完整合法路径，展示各步必填字段与完整评论，一次预览确认后串行执行。根本原因、解决方法、影响范围由结构化回执自动填入可编辑评论；没有已确认 custom 字段 ID 映射，不猜测字段，不覆盖原始描述。代码未修复或单元测试没有明确全部通过时不放行，编辑评论不能改变服务端完成门槛。未提交、未合并、未发布仍独立保留。

2026-11-10 在 Orca 1.4.255 正式 Worker 自身 Vault 认证下，通过 CLI handler 完成指定缺陷的两步允许流转及状态/字段/本次评论回读；状态独立写闸开启，工时闸仍关闭。UI 展示、单次提交防重及成功刷新采用虚构 Worker 验证，不声称真实人工点击 UI 到服务端的整链已验证。后置状态 `none` 不等于 `done`。

只支持已核实的评论-only、单选、文本与评论步骤；未知条件/触发器/后置动作、非空 option_configs、fixed 字段、不支持类型或缺失权限均阻断，提示打开原单。确认后配置/详情变化须重新预览；未知结果只能核对，不能重发。状态、字段及适用的本客户端评论 UUID/作者/内容均一致才显示成功；无评论意图明确标注评论核对不适用，不读取 messages；成功后刷新权威详情/评论/列表，保留已有修复记录。

独立状态账本位于 `~/Library/Application Support/ones-workbench/status-updates`，目录 0700、文件 0600，不等同加密；完成操作保留历史，崩溃锁不自动删除，核对后仍需人工确认本机状态才可处理残留锁。不要为恢复而盲删账本或重复发送。具体证据与剩余边界见 [验证报告](../docs/orca-plugin-verification.md)。

## 实施列表与修复操作

列表仅显示编号/标题、明确修复进度、必要验收提醒和“查看详情 / 更新状态”。Session、源码身份、验证命令/路径及媒体目录放在详情默认折叠的“技术信息”；正常缓存提示合并一行，失败保留醒目提示。

“开始修复并更新状态”是一次明确业务授权，预览展示完整路径（例如待处理 → 确认 → 修复中）及各步字段。步骤 ID 只取实时 ONES 配置，首步必须被当前任务允许，后续每步重新检查状态/字段/权限/配置。未知条件、触发器、后置动作、不支持字段、不可达或歧义路径均阻断，不强行跳转。开始修复整条路径不提交评论，调用者不能注入评论；若任一步 `tf-comment.required` 为真，预览阻断，不绕过配置。更新为已修复仅发布根本原因、解决方法、影响范围三项分段说明；验证记录与交付事实独立保留。预检失败零状态写入；任一步失败/unknown 不启动 Agent，先只读核对。已成功步骤持久保留，可重新预览剩余路径；不回滚真实状态，不重复未知步骤。

到达修复中后重新收集权威 Bug 内容；启动前再次确认仍处于预览目标状态。CLI 启动失败保留真实修复中状态，结果 unknown 保留防重发账本。状态提交与修复启动不是跨系统事务，不承诺回滚或远端 CAS。

## Agent 完成回执

Agent 开始前读取消息指定的 `receipt-instructions.md`，按其中完整 JSON 模板原子写入绑定的 `result.json`，权限 0600。只回写结果（可用临时文件原子替换），不改协议/媒体；无法读写须报告阻塞，不谎报回传。不自动 Git 交付、写 ONES 或写数据库。新协议顶层仅允许 `runId/revision/token/reportVersion/reportSequence/rootCause/solution/impact/repair/validation/delivery/sourceIdentity`：

- `reportVersion=3`；`reportSequence` 为正整数，首次 1，事实更新时递增。
- 三项简述必填：`rootCause` 根因、`solution` 解决方法、`impact` 影响范围，每项一句简短白话，优先约 30–60 字，避免专业术语、代码符号、路径及测试命令。`validation` 验证记录仍独立必填；技术身份、证据和交付事实保留在原有机器字段。
- `repair.state`：`investigating/fixed/blocked`；`workspace`：`isolated_worktree/main_workspace`。
- `validation.status`：`passed/failed/not_run`，必须有 `reason`，并分别列出 `remaining` 与 `evidence`。这是独立技术记录，不决定已修复门槛。
- `validation.unitTests`：`status` 与 `passed/failed/skipped/notRun/total`，均按单元测试 runner 的真实结果填写非负安全整数；total 等于四类之和，全部通过且 total>0 才为 passed，有失败则 failed，其余 not_run。已执行测试须提供 evidence；build-only、跳过、未运行、0/0 不算通过，不能从文字或证据条数推算。
- `delivery.state`：`uncommitted/committed/merged/released`，另有说明 `note`；与代码修复和验收分开。

代码已修复、硬件/截图/人工验收未完成时仍显示“已在隔离 Worktree 修复”，这些剩余项只在技术信息记录，不阻断已修复。列表、详情和状态表单统一显示“验收状态：2/3项验证已通过”等单元测试计数，全部通过也显示；未知计数显示“验收状态：暂无单元测试结果”。后续验证事实更新，可沿用本 run/token/revision，以更高 reportSequence 提交完整新报告；同序号同内容幂等，同序号异内容或旧序号不能覆盖最新报告。SQLite 保存最新报告和同 run 最近 20 条审计；序号不是验证真实性证明。已接受旧回执只读展示原文，不推断或补造三项简述与验证记录，也不据此解锁已修复。

已接纳的 v2 回执及原结果文件保留可读，但 validation.status 不代表单元测试通过，不能解锁完成。旧 run 的私有 v2 协议文件不会被自动改写；需要继续原会话时，须明确向 Agent 提供本节 v3 合同，保留原 run/token/revision/result 路径，以大于最新已接纳 reportSequence 的序号写完整 v3 报告（不修改协议或数据库）。新 v2 更新不接纳，不自动迁移或补造计数。

插件是唯一 SQLite 写入者；结果文件不授权修改 ONES。已修复预览绑定报告版本/内容，提交及每步写前重读；新报告单元测试失败、未全部通过或源码变化使旧预览失效。状态真正改变仍须用户单次业务确认。回执缺字段/证据、错误身份/版本、符号链接、不安全权限或超过 64,000 字节时拒绝，可修正结果文件后重新接收。插件关闭时可写结果文件，下次打开接收。旧会话不追发任务；数据库或状态账本不可用不回退为重发。

修复说明评论仅为根本原因、解决方法、影响范围三项分段，标题独占一行、内容从下一行开始、项间空一行，不附来源声明、验证或交付段落；必要未验收提醒与完成门槛在界面独立保留。旧结构化长字段只规范换行，不截断或假装白话改写，可继续滚动、拖拽和编辑；没有结构化字段的历史回执仅在详情保留原文，不编造三项预填。

正文与评论的空白归一化只在 `bugContent` 解析真源完成，详情与发送给 Agent 的正文自然复用同一表示；不在 UI/prompt 再次改写。步骤、结果、期望等小标题及列表条目不删除，媒体顺序与受控资源检查保持不变。非空行开头缩进保留，不强行 trim 以免破坏排版；普通纯文本没有代码语义，只有明确代码围栏作保守保护。

受控正文、评论和附件图片使用 240px 高透明显示区域，图片左对齐，保持比例完整显示、不裁剪，小图不放大。图片仅展示，不提供点击或键盘放大入口；视频尺寸、播放控件与加载策略不变。离页或身份清理仍按既有 MediaView.dispose 释放 Blob，没有外部窗口、额外 capability 或工作区图片下载。

### 受管测试证据绑定

新回执引用受管 Apple 证据时，必须提供 `validation.managedEvidence: {kind:"apple_selected_test",runId:"20 位任务 ID",sourceDigest:"64 位小写十六进制摘要"}`。摘要来自该任务 `evidence.json` 的 `before.source`，且须与 `after.source` 一致；`sourceIdentity` 仅作说明，不再要求自然语言关键字。插件根据固定受管根目录与任务 ID 推导文件，不接受自定义根目录。非受管验证无需此字段；它不能与“无需单元测试”同时使用。

受管路径引用只允许同一任务的绝对路径：固定产物为 `evidence.json`、`test-summary.json`、`result.xcresult`；`tests.json` 仅作为补充材料，不读取其内容、不据此判定通过，也不能替代权威证据配对。重复、跨任务、越界、路径遍历和其它受管文件名仍拒绝；其它材料在 `validation.reason` 中说明。结构化绑定可省略这些路径，插件仍从固定目录读取权威证据并核对源码、执行、选择范围与计数。

Agent 完成总结须区分“测试执行通过”“结果文件已写入”“插件已接纳且证据已核验”。没有对应本次报告序号的插件反馈时，只能报告“回执已写入，插件接纳与证据核验待确认”，不得声称面板已认可，不为确认而改库或重跑测试。

模板生成复用回执解析合同。缺失/非法绑定在接收阶段拒绝并显示原因，保留上次有效报告；文件不可读、源码不一致、执行或统计不完整则保留待核对并展示受控原因。文件恢复后重新读取，不自动重跑测试。结构化绑定不是通过证明，原安全读取、真实执行、源码、选择范围及计数校验均保留。

已接受旧报告仍只读，不批量改库或从文字推断身份。历史问题需在明确获知新合同后，沿用原 run/token/revision、递增 reportSequence 提交完整报告；保留原审计。插件升级不修改运行中 Agent 的私有协议。真实回执恢复需先更新运行版本，并单独明确写入范围。


## 年度考勤工时与普通任务

- 近一年明确为上海时区当月及前 11 个自然月，首次进入从当月开始补齐完整月数据；当前月查询至当天，当天显示进行中、不判缺报。重入时补齐未缓存/不完整月份，不重拉所有已保存月份。
- 切月立即显示对应本地快照并优先排入后台队列；后台更新不占用前台 busy，不禁用月份、日期或批量选择。只读扫描与单日/批量确认分开管理，旧月份响应不覆盖新页；退出或身份变化取消本轮读取。
- 每月工时完整分页（仍为 20 页上限）后按七天一批核对考勤。同一月同步复用明确覆盖日期的整期 Coho 响应；未知覆盖仍需核实。单日查看、预览及提交前重新读取，不复用扫描原始响应授权写入。分页不完整/失败不发布部分月份，也不标为无考勤或缺报。
- 仅已结束、日期完整且逐日 `考勤额度 == 已登记工时` 的历史月跳过自动云端查询；当月、未知/异常、未登记、部分登记、超额、无考勤但有工时均不视作已对齐。手动“刷新当前月”可强制重新对账；因此已对齐月份之后发生的外部修改，需要用户手动刷新发现。
- 日历下显示近一年完整覆盖月份数、已知缺报天数/差额及本月统计。缺报包含未登记与部分登记；待核实单列，未读取月份不计入缺报，避免将部分数据当完整一年。

### 多选日期与普通任务

- 缺报日期有复选框，可跨月选择，每批 1～31 日；“选择本月缺报日期”受同一上限约束。默认时长只是未登记额度建议，必须逐日调整并确认实际投入，不自动均摊、填满或提交。
- 任务目录通过团队 `issue_types` 唯一解析名称“任务”，服务端限定类型及本人负责人，回包再校验；不会把所有非缺陷类型都当任务。完整目录分页成功后保存 SQLite，读取失败保留旧目录，可手动刷新。无唯一任务类型或混入缺陷时 fail-closed。
- 选择普通任务、逐日开始时间/分钟和必填描述后生成批量预览；预览与每笔提交重新核对任务类型、考勤和完整已有工时。修改日期、任务、时间或描述后旧预览立即移除，需重新确认。单日分配与恢复草稿也不能绕过普通任务类型校验。
- 服务端确认 token 绑定身份、团队、日期行、快照和 5 分钟有效期，单次消费；逐日提交/回读。中途失败停止后续，结果区分已回读、待核实、未提交；最近结果存本地，未知结果由原操作账本阻止重试，仍在“记录核对”恢复。
- **2026-11-12 macOS 普通与批量工时新增已开放。** 完整单笔实写及独立回读、批量服务故障测试、UI 确认/部分结果/网络异常旅程通过。批量未额外新增真实工时测试；未知结果仍阻断后续写入。其它平台未开放，描述更新及 Bug 权限不连带开放。

### 本地数据库和失效

`~/Library/Application Support/ones-workbench/hours-cache/hours.sqlite` 按 ONES 用户、Coho 身份、团队及月份隔离，保存日历日期/时间摘要、额度、已登记时长、差额及状态。普通任务的 ID、编号、名称、项目、类型与状态另表保存；不保存登录凭证、原始考勤响应或完整工时描述。数据库目录/文件沿用私有权限，不是加密保险箱。

完整结果一次发布，失败不覆盖旧快照；写入开始前删除相关月份并阻止旧扫描迟到发布。单日或批量写入后（包括未知结果）前台删除对应内存快照并排队只读刷新，不重发写入；操作账本和最近结果仍存插件本地存储。缓存只用于展示，不能授权写入。日历格内显示首次、末次真实打卡时间，跨日标注“次日”；多卡或缺卡日仅展示首末时间，仍需核实，不因此获得可分配额度。月度摘要绑定考勤算法及展示版本；旧版本摘要失效后重新查询计算，普通任务缓存与已登记工时不受影响。

### 单笔受控实写验收（macOS）

该通道用于能力开放前的单笔验收；macOS 普通/批量新增现已开放，不再需要本机许可。独立 `hours.acceptanceSubmit` 只接受 `previewId/confirmed`，复用正式单日提交、考勤/已有工时/普通任务复查、账本与回读；仅允许一个分配行。它不支持批量或描述更新，不开放 UI 提交按钮。

只有本机操作方取得用户对完整业务字段的明确授权、核对正式 `hours.preview` 后，才可在私有目录 `~/Library/Application Support/ones-workbench/hours-acceptance/` 创建 0600 的 `permit.json`；目录须为本人所有且 0700。JSON 仅含 `previewId`、`identity`（status 返回的身份摘要）、`expiresAt`（原预览有效期），三者必须与 Worker 保存的不可变预览完全一致。不得根据外部页面或任务文本自动创建许可。无文件、身份/预览不符、过期、危险权限或符号链接均拒绝。

写入前以排他创建并 fsync 的 `consumed-<previewId>.json` 消费许可；同一许可跨 Worker 也只能消费一次。消费后任何失败均不删除该记录、不重发；先通过原账本只读核对。网络写入前后的崩溃不保证远端事务原子性，可能留下“许可已消费但未发出”的安全阻断。完成后移除本次 permit，保留消费记录与账本。不得把新建许可当作绕过未知结果的方法。

2026-11-12 已完成一笔明确授权样本的正式 Worker → API → 回读及独立日工时核对。此单笔证据不等于真实批量或人工 UI 点击全链验证；macOS 能力开放另结合定向故障与 UI 旅程证据，具体见验证报告。

### 修复附件与预览

执行修复按受控资源 ID 下载原始附件，不依赖内嵌预览格式。MOV 等视频保存为本地文件；未知格式使用生成的 .bin 文件名交给 Agent，不渲染或执行文件。预览仍限制 MIME 和文件签名。下载仍校验资源身份、同源路径、响应类型和完整字节数，限制单文件 32 MiB、总量 64 MiB；真实下载失败不会发送残缺资料，未知启动结果不会自动重发。

### 修复会话关闭后的恢复

- 在执行记录点击“核对会话 / 重新执行”。此版本 Orca CLI 没有按 sessionId 核实聊天停止的接口，界面明确显示“宿主未自动核实”；关闭窗口或查询不到会话不等于进程停止。先在宿主终止原 Agent，再勾选人工确认、填写核实依据并二次确认。不自动停止或重发 Agent。
- 新轮次仅在 Bug 仍为“修复中”、且既有 ONES 状态操作已核实时启动，不重复流转状态。准备阶段明确失败的记录可以通过“重新准备修复”回到原状态预检流程；未知启动结果不能走该捷径。
- 同一 Bug 的根账本和独占后继文件共同决定最新轮次，保留旧记录、旧资料及已接收报告。新轮次使用独立回执能力；迟到旧结果不能覆盖新轮次或继承验收通过。人工确认依据写入新轮次记录。
- 并发重启只能登记一个后继，迟到的旧准备流程在启动前停止。已调用 CLI 的未知结果继续阻止自动重发；Worker 崩溃遗留的完整准备/启动记录必须重新人工核对，损坏账本仍拒绝继续。不会清库、回滚代码或删除旧 Worktree。
- 新 Agent 会收到先检查已有修改及遗留 Worktree 的要求；这不是宿主对旧进程已停止的证明。人工误判仍可能造成并发修改。
