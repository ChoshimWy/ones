# ONES 工作台：Orca 插件功能与实施规划

## 1. 目标、范围与状态

规划两条闭环：**Bug → Orca 实施 → 人工验收**，以及**考勤 → 有效工时 → 手动分配 → ONES 登记**。采用 Orca 插件；2026-11-09 最终改用仅插件 HTML + Blob 方案，范围和验收见第 10 节；第 9 节宿主扩展保留为历史，不再作为交付依赖。

本文合并功能、关键设计与实施计划，按 L3 处理认证、业务写入与 Agent 启动边界。文档生成获准不等于代码实施、插件安装授权、真实业务写入、Git 交付或发布授权；已获用户“根据方案开始实施并验证”授权，开发原型已实现并临时加载；未闭合项仍阻塞对应功能，完整方案未验收。实际结果见 [VR-ONES-PLUGIN-001](orca-plugin-verification.md)。

需求唯一真源为 [TSD-ONES-001 §1](ones-api-integration.md#1-结论与范围)，接口沿用该文档；考勤算法唯一真源为 [TSD-COHO-001 §6](coho-attendance-api.md#6-已确认的工时规则)。本文不复制请求结构或算法，不将历史单笔 API 实测扩大为插件端到端验证。

2026-11-09 用户进一步明确的产品约束：**通过插件界面输入账号密码并提交认证；新增工时必须基于对应日期的 Coho 考勤。** 登录交互合同在第 2.3 节定义，考勤强制前置在第 4.2 节定义；两者是已确认需求，不是已验证的实现能力。

| 功能 | 首版边界 | 可观察完成条件 |
| --- | --- | --- |
| 连接设置 | 插件分别提供 ONES、Coho 账号/密码表单与登录提交；团队/项目选择，人工确认两站账号映射 | 各站独立认证并回读身份；过期停止；不依赖浏览器登录态；切换账号后旧草稿不能直接提交 |
| 我的 Bug | 项目、负责人、状态筛选，列表/详情，打开原单 | 类型与权限来自元数据；分页完整性可见；不把失败显示为空列表 |
| 发起实施 | 选择授权仓库、基线、Agent，关联隔离工作区与实施记录 | 重复发起可识别；原 ONES Bug 类型与状态保持不变 |
| 考勤与额度 | 选择业务日期，读取打卡，展示额度及异常 | 已确认规则可解释；缺卡、跨日等不擅自补值 |
| 手动分配 | 选择 Bug/普通任务，填开始时间、时长、描述，保存草稿 | 展示额度、已有、本次及剩余；不自动均摊，不强制填满 |
| 工时提交 | 以所选日期的有效考勤为前提，手动分配后逐笔确认、提交、回读及恢复 | 无有效考勤依据不得新增；描述非空且获确认；不超额；未知结果不盲目重试 |
| 补全描述 | 定位原记录，确认目标文本，仅补描述 | 原 key、日期、时长、归属、条数与合计保持不变 |
| Bug 写入 | 后续阶段单独开放新建、内容修改、状态流转 | 动态字段、权限、并发变化与回读契约补齐后才启用 |

非目标：脱离考勤直接新增工时、自动关闭 Bug、无人确认的自动填报、替他人填报、根据 Agent 时长推算工时、批量流转、自动评论/附件上传、删除工时或删除 Bug、自动提交代码及自动清理工作区。首版运行于本机 Orca；远程执行主机接入另行验证，不将本机路径用于远端。

## 2. Orca 能力事实与技术路线

### 2.1 已核实的宿主边界

EV-PLUGIN-001：2026-11-09 读取本机 Orca 1.4.253 的 `skills get orca-plugin-authoring`、`references/host-api.md`、`references/manifest.md`、`plugin create --help` 及安装包 `orca-local-build.json`。以下仅是当前版本文档/类型能力，未运行插件或验证网络与授权链路。

| 能力 | 发现结果 | 实现决策 |
| --- | --- | --- |
| 插件入口 | 早期 `worker-panel` 脚手架；最终 HTML 面板 + TypeScript Worker（§10） | DEC-PLUGIN-001：以独立插件侧栏实现，不侵入宿主 |
| 执行模型 | `trusted-worker`，插件安装/加载需对应权限同意 | 将真实授权列表展示给用户；不因本文自动批准 |
| 内置任务源/连接扩展 | guide 标为 reserved，尚不可构建 | 自有 Bug 列表与连接设置，不伪装内置任务源 |
| 面板网络 | 沙箱面板不能任意联网 | 网络访问集中 Worker；网络可达性与受控请求方案需 P0 验证 |
| 凭证与普通数据 | `secrets:own`、`storage:own`、`settings:own` | 先检查 `secrets.protection`；保护不可用时禁止明文降级 |
| 工作区 | Host API 可 list/open，无直接创建方法；CLI 有 `worktree create` | DEC-PLUGIN-002：创建使用经核实的受控 CLI 适配，不假设不存在的 API |
| Agent 启动 | Host API `agent.launch` 文档描述 CLI terminal；CLI launch 支持宿主启动选择与回执 | 两者不可视为等价；P0 选定唯一启动路径并冻结返回合同 |

最终最低版本为 `>=1.4.254`，HTML 媒体验证以此版本为基线；不承诺旧版本兼容。实施时按实际使用 API、宿主版本与 `host.has` 重新核对。技术方案不依赖远程公开文档比本机更“新”。

### 2.2 模块与权限

```text
插件面板（我的 Bug / 实施记录 / 考勤与工时 / 设置）
  → 有类型的 panel-worker 请求
    → ONES Adapter / Coho Adapter / 工时服务 / 实施服务
      → 受控 HTTP、凭证库、本地操作记录、Orca Host/CLI Adapter
```

实施目录为 `plugin/`，实际模块路径以源码为准；下列为职责划分：其中 `orca-plugin.json`、`src/html/`（入口 `src/panel.html`）、`src/worker.ts`、`src/domain/`、`src/adapters/`、`src/protocol.ts`、`tests/` 分别承担声明、UI、用例编排、纯业务规则、外部适配、协议及定向测试。`plugin/tests/` 使用虚构数据，不能复制根目录被忽略的测试/配置与原始数据。实施时明确插件打包与依赖锁文件，不先构建通用 Provider 框架。

- UI 不接收访问令牌、原始考勤响应或任意 GraphQL；Worker 只暴露具名业务操作并校验输入、账号和范围。
- 非敏感设置存 `settings:own`；凭证存 `secrets:own`；草稿、关联关系与脱敏操作记录存本地 `storage:own`。普通存储不视为加密保险箱，默认不持久化原始考勤与完整 Bug 正文。用户授权的月度日历摘要单独存 SQLite，按两站身份、团队和月份隔离，不作写入凭据。
- 按功能逐步申请 `workspace:read`、`workspace:write`、`agent:read` 等实际必需权限；`agent:launch` 仅在所选 Host 启动路径需要时申请。不默认申请终端读写、全局 hooks 或外观权限。
- `trusted-worker` 与 Node/子进程带来本机代码执行风险；Host capabilities 不是其完整操作系统沙箱。网络白名单、禁止重定向、固定 CLI 路径与 argv 校验需插件自身实现并验证。
- 仅允许现有文档指定的 ONES HTTP origin 与 Coho HTTPS origin；HTTP 明文风险必须可见。认证、刷新与独立登录未闭合时只禁用依赖功能，不猜测登录接口或读取全部浏览器存储。

### 2.3 插件账号密码认证

DEC-PLUGIN-007：正式登录入口是插件自有界面，不要求用户先登录 Orca 浏览器，不以浏览器令牌复制、Cookie 导入或读取 localStorage 作为正式认证路径。ONES 与 Coho 分别输入账号、密码并点击登录；Coho 所需租户使用明确配置，不复用另一站的凭证。

```text
选择站点 → 输入账号/密码 → 点击登录
  → Worker 校验目标 origin 与必要配置 → 调用该站认证接口
  → 检查业务响应 → 回读当前身份 → 返回脱敏连接状态
```

- 密码使用遮罩输入、仅保留提交所需的临时内存；不进入持久化 atoms、草稿、settings、普通 storage、事件日志、截图取证、CLI 参数或 Agent 提示词。请求结束、取消或面板关闭后清空输入和持有引用，不承诺 JavaScript 内存物理擦除。
- 仅认证 handler 接收密码；panel-worker 桥接及错误记录须验证不记录请求体。Worker 按已核实站点协议编码密码，编码后的 credential 同样视为秘密，不硬编码或输出。
- 默认不保存密码；需保留登录状态时，只将必要令牌保存于受保护的 `secrets:own`，不回传给 UI；秘密保护不可用时禁止明文持久化。账号展示与连接状态不携带认证材料。
- ONES 登录提交前明确展示 HTTP origin 和明文传输风险；仅用于指定可信内网/VPN。密码加密或摘要不能替代 TLS；禁止自动重定向及跨站转发凭证。
- 登录成功以业务响应和当前身份回读为准。错误密码、权限不足、租户不符、网络异常、认证过期分别提示；不显示原始服务端响应，不自动循环重试密码。验证码、SSO/MFA 等未支持分支明确阻塞，不静默绕过。
- 两站连接状态相互独立：Coho 未认证不阻止已认证 ONES 的 Bug 读取，但不能新增工时。两站都登录后，仍须确认 Coho 员工归属与 ONES 用户映射，不能凭姓名相同自动绑定。
- 登录/退出/切换账号具有连接代次；取消或切换后的旧响应不能重新激活旧身份。退出清除该站令牌并使相关确认失效；保留必要的待核实写入记录用于后续恢复，不混用不同账号的草稿。
- ONES 独立账号密码登录合同尚未验证；Coho 已有独立登录样本，但租户配置、员工 ID 解析及插件链路仍需核实。P0 必须补齐后再启用对应登录，不能把此次产品决策标为登录实测成功。

## 3. 页面与交互合同

这是功能交互规划，不是已完成高保真设计或视觉验收。实施采用 HTML 原生控件与 Orca 宿主主题变量，不另造独立视觉系统。

| 页面 | 关键交互 | 必须区分的状态 |
| --- | --- | --- |
| 我的 Bug | 筛选 → 列表 → 详情 → 原单/发起实施 | 加载、空结果、无权限、离线、认证过期、分页不完整、详情已更新 |
| 实施记录 | 查看 Bug 关联、工作区与 Agent；打开已有实施；人工验收 | 待发起、启动中、启动待核实、实施中、受阻、待人工验收、已验收 |
| 考勤与工时 | 日期 → 核对考勤 → 手动分配 → 提交预览 → 逐笔结果 | 异常考勤、已有工时不完整、草稿失效、超额、部分成功、结果待核实 |
| 设置 | ONES/Coho 独立账号密码表单、登录提交、退出/切换账号，身份及项目/仓库映射 | 未登录、认证中、登录失败、已连接、过期、保护不可用、访问受限 |

- 功能不可用时保留入口并说明原因；提交预览完整展示业务日期、账号、任务、开始时间、时长及描述。
- 写入后保留逐笔结果；不能用统一“成功”覆盖失败/未知项。按钮防连点只是 UI 保护，Worker 仍需防重。
- 用户切换工作区不会改变已固定的提交或实施目标；身份/团队/日期变更使相关确认失效。
- 采用明确字段标签、键盘可达焦点和非颜色唯一的状态提示；浅/深色、错误、长标题与窄面板在实际 Orca 中验证。未生成 UI 前不宣称布局或可访问性通过。

## 4. 状态、身份与业务不变量

### 4.1 Bug 发起实施

DEC-PLUGIN-003：来源身份沿用 `instanceId + teamUUID + taskUUID`；显示编号仅供展示。实施关联记录保存来源身份、详情版本、用户选定的仓库/基线 SHA、工作区身份、启动操作 ID 和返回的 Agent handle；Agent handle 按宿主生命周期重查，不永久复用失效值。

执行顺序：重新取 Bug/权限 → 选择仓库、基线与 Agent → 预览最少必要任务说明 → 查询已有实施 → 创建隔离工作区 → 启动或恢复已有启动 → 保存关联。

- Bug 富文本是外部数据，不能成为指令授权；不自动执行正文命令；仅为用户打开的详情按第 9 节合同读取展示所需媒体，不批量下载无关附件。传给 Agent 的内容须去除凭证和不必要个人数据。
- 默认一个来源 Bug 的活动实施只能由一个本地操作持有；同 Worker 串行化，持久记录启动意图。崩溃/多进程后的互斥保证需 P0/P3 验证，不假设 `storage.set` 支持 CAS。
- 使用固定可执行文件和参数数组，不经 shell 拼接 Bug 文本。CLI 创建的 worktree 路径必须符合本仓规则；基线完整 SHA 与所有权在创建前冻结。路径不可满足时停止，不回退原工作区写入。
- 工作区创建与启动结果分开记录。启动超时先核查操作回执/实际工作区与会话；如宿主提供 replay ID，按该版本合同重放同一请求，不无条件创建新工作区或新 Agent。
- 不同时调用 Host launch 与 CLI launch。部分成功保留已创建资源并展示恢复入口，不自动删除可能已有用户修改的工作区。
- Agent 报告完成只进入“待人工验收”；插件人工验收状态与 ONES 工作流状态分开。未收到可信终态或归属不明确时显示未知，不把会话消失当成完成。

### 4.2 考勤、分配与提交

DEC-PLUGIN-004：新增工时必须基于所选业务日期的本人 Coho 考勤；工时计算与分配分离，考勤只生成有效额度，用户决定任务分配。详情见 [考勤规则](coho-attendance-api.md#6-已确认的工时规则) 与 [分配约束](ones-api-integration.md#53-考勤到任务的分配规则)。

新增入口必须遵循下列顺序，任务详情中的“添加工时”也应进入同一流程，不能绕过：

```text
两站认证有效 → 自动读取当月/切换月份 → 选择日期 → 重读对应考勤
  → 校验打卡/处理异常 → 按既有规则生成有效额度
  → 完整读取本人当日已登记工时 → 用户手动分配任务
  → 确认日期、开始时间、时长与描述 → 提交并回读
```

- 未登录 Coho、读取失败、无记录、身份/日期不匹配、异常未解决时，“新增工时”禁用并提示原因；不能默认填入 8 小时，也不能用手输总额度替代考勤读取。
- 异常人工确认只能基于已取得的对应考勤及已确认规则，记录确认依据；无法确定有效额度时保持阻塞，不能用“人工确认”跳过缺失数据或自行制定迟到/缺卡政策。
- UI 展示考勤日期、必要打卡摘要、折算依据、有效额度、已有工时和剩余额度。Worker 写前同样校验，不能只依赖按钮禁用；所有面板、命令入口复用同一新增校验。
- `本次待新增合计 ≤ 考勤有效额度 − 本人当日已登记合计`；右侧小于或等于零时不能新增，不自动修改已有记录。不允许用户通过关闭考勤校验、改日期或改任务绕过额度约束。
- 用户只能在可用额度内手动分配，不把额度直接当成某项任务耗时；不自动填满。预览、草稿恢复和提交使用同一业务日期，不能将历史考勤写成提交当天。
- 补全原记录描述不增加工时，不受“新增必须读取考勤”的新增额度条件约束；仍需原记录完整唯一定位、身份验证与单独确认，不能借补描述修改时长或日期。

草稿绑定 ONES/Coho 身份映射、团队时区、业务日期、考勤依据版本、完整已有记录快照、任务身份、开始时间、整数时长与描述。人工分配输入粒度尚未确定，P0 按团队限制明确；不能把考勤半小时折算直接当成所有录入项唯一粒度。

DEC-PLUGIN-005：每笔写入遵守“意图持久化 → 提交 → 回读 → 核对”，而不是“请求返回即完成”。本地状态建议为：

```text
draft → confirmed → submitting → verifying → verified
                         ├─ 明确拒绝 → failed
                         └─ 超时/崩溃/不明响应 → unknown → 核对后确定结果
```

- `confirmed` 绑定本次完整预览；字段、身份、权限或额度变化后必须重新确认。重启后 `submitting` 视为待核实，不重新自动发送。
- 本人当天完整已有登记工时与考勤均有效后才能提交；切换账号、日期或考勤修订使旧核对失效。缓存只能展示，不能代替写前权威读取。
- 同一身份/日期的批次本地串行，逐笔回读并更新剩余额度；部分失败或结果不明时暂停批次剩余项。其它设备仍可能并发写入，不能承诺跨客户端强一致或 exactly-once。
